# DiscordIntegration review

DiscordIntegration is a substantial connector-readiness preview rather than an active Discord integration. The screen preserves its local search and requirement filters while explicitly disclosing that no OAuth client, bot token, guild directory, role provider, channel data, webhook, message gateway, or event subscription is connected. Unavailable refresh, settings, connection, credential, invite, synchronization, and per-requirement management actions only update an in-page live status message; they do not contact Discord or mutate credentials, permissions, guilds, channels, messages, notifications, or synchronization state.

The page presents identity, server, message, and synchronization availability cards, plus typed requirements for OAuth identity, guild and role permissions, channels and messages, and events and notifications. It also states the safeguards required for a production connector: OAuth consent, token isolation, least-privilege scopes, server approval, moderation ownership, webhook verification, rate limits, retention, revocation, and audit logs. The route is keyboard-usable through labeled search and buttons, and status updates are announced with `aria-live`.

Prettier, `tsc --noEmit`, and the production build completed successfully. Desktop evidence shows the full connector boundary, availability cards, local filters, requirements, and unavailable management controls. Mobile evidence shows a readable stacked hierarchy with the connector-unavailable disclosure and identity/server availability state visible at 390×844. No Discord identity, guild, role, channel, message, event, synchronization result, or credential is fabricated.

# TextInputForm visual findings

The 390×844 mobile render keeps the text-input header, unavailable service disclosure, reset control, form preview, labeled textarea, and local input boundary readable while allowing the form to continue below the viewport. The 1440×1000 desktop render presents the full form workspace with a clear textarea, character count, required-field semantics, local status region, selected form-state metadata, persistence/moderation/delivery/submission boundaries, and privacy guidance. The implementation uses a labeled textarea, `aria-describedby`, `aria-invalid`, `role=alert` validation feedback, `aria-live` status messaging, a 280-character local limit, and keyboard-submit behavior. No text is persisted, moderated, delivered, submitted, or treated as a real message, ticket, application, prompt, or saved record.

# SKYCOIN4444 Preserve-and-Expand Policy

Every existing screen is treated as a product asset. Modernization must preserve meaningful feature areas, routes, navigation, controls, data relationships, and domain language unless a specific behavior is demonstrably unsafe or misleading.

## Expansion first

A screen should gain product depth through richer information architecture, detail views, tutorials, setup guidance, search and filters, saved preferences, recent history, comparison, progress, retry behavior, accessibility, responsive layouts, and integration-ready state models. A placeholder capability should become a clearly labeled extension point with the surrounding UX needed for a real future integration—not disappear.

## Narrow honesty corrections

Only unverified claims are eligible for removal or relabeling. Examples include fake player counts, fake balances, fake payout success, unsupported production metrics, invented transaction confirmations, nonexistent analyzer counts, and claims that a service has completed work when no service contract exists. The underlying product area must remain visible as unavailable, pending, demo, practice, or integration-required.

## Report discipline

Every screen report must distinguish preserved features, newly added features, honesty corrections, real integrations verified, blocked integrations, validation results, and the commit checkpoint. A `PARTIAL` screen means the frontend experience is substantially improved while one or more real backend or authenticated contracts remain unverified; it does not mean the feature was removed.
